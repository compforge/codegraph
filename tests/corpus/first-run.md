## 已核对的差异模式

1. **结构体字面量键误绑到同名类型或变量**：agentgo 的 `message.go` 中 `Message{Role: ...}`，
   编译器目标是 `Message.Role` 字段，图中的 exact 引用目标是 `Role` 类型。
   repocli 的 `cmd/root.go` 中 `cobra.Command{Version: Version}`，左侧字段键误绑到本地 `Version` 变量。
   全部 20 条错误 exact 引用均呈现字段目标与同名其他声明的差异。
2. **链式调用的外层目标与内层函数混淆**：agentgo 的 `schema.Property(...).Required()`，
   外层调用应指向 `Required`，对应 exact 边却指向 `Property`。
   14 条错误 exact 调用均为外层方法与内层函数错配，涉及 Required、AsTool、ToAgentMessage。
3. **提取和绑定是不同层次**：go-stdx 的标识符使用位置全部被提取，但内部引用目标仅命中 66/125。
   对应已建模字段的引用也纳入目标召回，未命中不自动意味着违反当前绑定能力承诺。
4. **其他待处理差异**：repocli 少提取了一处名为 `close` 的内部标识符使用；agentgo 输出了一条
   名称为 `_` 的声明，参照口径排除空白标识符，因此记录为额外输出。详细位置保留在原始报告。

参照器已有独立小型契约验证字段键、链式调用和导入别名的目标；没有把错误图输出保存成正确答案。
本轮保留这些质量失败，未把修复绑定实现混入测试基础设施改动。
